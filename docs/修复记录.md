## 2. 架构与运行原理（修复所依赖的理解）

自研 **FFM1（Forge & Fabric Mixin One）** 框架，一个 JAR 同时覆盖 Forge / Fabric / NeoForge 与 MC 1.16.2–1.20.2：

1. 外层是 `modloader` 产物：Fabric 侧 `fabric.mod.json` 声明嵌套 jar（`META-INF/core/fabric-mixin.jar` 与 `mod.jar`）；Forge 侧通过 `META-INF/services/...IModLocator` 把 `mod.jar` 与 `forge<ver>.jar` 作为 `explodedTargets` 注入。
2. `mod.jar` 含 `MainMod`（动画主逻辑）、`game:api` 桩类与平台入口（`FabricLoader` / `ForgeLoader`）。
3. 每个 `game/fabric1.*`、`game/forge1.*` 目录提供同名类的真实实现，打包为 `META-INF/core/*.jar`。
4. 运行时 `VersionMapping.get(mcVersion)` 选 core：Fabric 侧 `modloader` 的 `MixinPlugin` 反射 `GameTransformer.patchedClasses` 把 core 内类直接注入；`fabric-mixin` 的 `MixinPlugin` 按构建期生成的 `<MIXINS_JSON>` 选择 mixin 列表。Forge 侧由 `ModLocator` 完成模组发现。
5. `MainMod.preRenderCrossHair` 计算视角摇晃、挥手、切物品、潜行、食用、弓/弩/三叉戟蓄力、攻击暴击，对 HUD `MatrixStack` 做 push→变换→pop。
6. Fabric 用 `InGameHudMixin` 注入 `InGameHud.render`；Forge 用 `RenderGameOverlayEvent` / `RenderGuiOverlayEvent` 的 CROSSHAIR 阶段。

Mojang 1.20.1 官方字节码证据：`Gui.render` 偏移 321 调用 `renderCrosshair`，偏移 331 才是 `profiler.push("bossHealth")`；1.20.2 同样存在该标记。原模组把 post 注入点绑在 `bossHealth` 字符串上，属于跨版本脆弱设计。

## 3. 已确认问题与修复明细

### P0 —— 构建阻塞：失效的 TaCZ Fabric 编译依赖（新增，官方仓库自身缺陷）

- **现象**：未修改源码的基线 `gradle buildMod` 直接失败：`Could not find maven.modrinth:timeless-and-classics-zero:kjph7s7Y`（HTTP 404），耗时 5m28s 后 `BUILD FAILED`。日志 `research/baseline-build.log`。
- **根因**：PR #15 为 `game/fabric1.20` 加入 TaCZ 的 Fabric 兼容构建依赖，该 Modrinth 版本已下线；且该目录下的"TaCZ 兼容"代码直接 import 了 Forge 类（`com.tacz.guns.api.client.event.ViewportEvent`），在 Fabric 运行时必然 `NoClassDefFoundError`。Modrinth 上 TaCZ 的 34 个版本 `loaders` 全为 `forge`，官方并无 Fabric 版——这段兼容代码从未实际生效。
- **修复**：
  - `game/fabric.gradle`：移除失效的 TaCZ / Porting-Lib 依赖与 devos 仓库，保留 modmenu / cameraoverhaul。
  - 删除死代码 `game/fabric1.20/.../game/api/mod/TacZ.java`、`.../mixin/RenderCrosshairEventMixin.java`。
  - `game/fabric1.20/.../Player.java`：移除 `IGun` / `TacZ` 引用与两处判断（潜行、切物品），恢复该版本原本的纯原版逻辑。
  - `game/fabric1.20/.../Render.java`：移除 Forge 类 `ViewportEvent` / `CameraSetupEvent` 引用与 TaCZ 分支。
  - **Forge 侧 TaCZ 兼容保留**（真正有 TaCZ 的平台），见 P6。
- **依据**：基线构建日志、Modrinth 版本 API、`fabric.gradle` 与源码交叉核对。

### P1 —— issue #11：Quilt 0.26.3 启动崩溃（已确认根因，有堆栈）

- **根因**：`modloader/.../loader/fabric/MixinPlugin` 反射 `patchedClasses` 注入 core 类；Quilt 的 GameTransformer 结构不同，注入失败后 Mixin 预处理期找不到 `krash220.xbob.game.api.bus.PlayerBus`，`class_1309` 转换失败。作者回复"无法修复，将移除兼容标记"。
- **修复**：
  - `modloader/.../utils/FabricQuiltUtils.java`：新增 `isQuilt()`，以 **impl 类** `org.quiltmc.loader.impl.QuiltLoaderImpl` 是否存在判定（原来只凭 API 类，见 P2）；移除全部 Quilt 内部类编译期引用。
  - `modloader/.../loader/fabric/MixinPlugin.java`：检测到 Quilt 时**跳过 core 注入**（打印明确说明，不抛异常）；`fabric-mixin/MixinPlugin.getMixins()` 返回空列表；`src/modbase/.../FabricLoader.java` 入口点检测 Quilt 后直接返回。
  - `modloader/build.gradle` 移除 `org.quiltmc:quilt-loader:0.17.0` 编译依赖。
  - 效果：**Quilt 上游戏正常启动、本模组不生效**（不再晦涩崩溃）。这是作者原本打算做的"移除 Quilt 兼容"，但以优雅降级而非报错退出的方式实现。
- **剩余限制**：Quilt 上功能不可用（原版也不可用）；若 Quilt 未来改掉 impl 类名，检测会失效——已在文档中如实说明。

### P2 —— issue #18：Fabric Loader 0.19.3 启动崩溃（已确认根因，有堆栈）

- **根因**：`FabricQuiltUtils.isQuilt` 只凭 `Class.forName("org.quiltmc.loader.api.QuiltLoader")` 判定；某些环境（issue #18 的日志包）只有 Quilt **API** 类、缺 impl 类，于是误判为 Quilt 并硬引用 `QuiltLoaderImpl.INSTANCE` → `NoClassDefFoundError: org/quiltmc/loader/impl/QuiltLoaderImpl` → 两个 `MixinPlugin.onLoad` 失败 → ARRP 类加载连带失败。
- **修复**：同 P1，检测改为 impl 类；Fabric 环境一律走 Fabric 路径（已用 `javap` 确认 0.14.14 / 0.19.3 均有 `patchedClasses` 字段）。
- **证据**：`research/evidence/issue18-extracted/` 日志堆栈、`fabric-loader-0.19.3.jar` 类清单。

### P3 —— 版本越界静默套用 1.20.2 实现（issue #7/#8/#17 的共性缺陷）

- **根因**：`VersionMapping.get()` 对任何 >1.20.2 的版本（1.20.3、1.21、25.x、26.2）都返回 `"1.20.2"`，于是加载版本不匹配的 core → Mixin 目标错乱崩溃；而 `displayError` 只在 core 文件缺失时触发，永远不会给出可读原因。
- **修复**：`VersionMapping` 增加 `MIN_SUPPORTED=11602` / `MAX_SUPPORTED=12002`，越界返回 `null`；新增 `getSupportedRange()`；`modloader/fabric/MixinPlugin`、`modloader/forge/ModLocator`、`fabric-mixin/MixinPlugin` 对 `null` 给出明确错误/禁用 mixin，不再加载错误实现。
- **注意**：这是"优雅拒绝"，**不是**新增 1.21/26.2 支持（作者已宣布停更，需整套重写）。

### P4 —— 快照版本映射错误

- **根因**：`SNAPSHOT_PATTERN` 分支用连续 `if`（非 `else if`）且从旧到新赋值，靠后的旧条件覆盖新条件（如 23w12a 被算成 1.19.4）。
- **修复**：改为从新到旧的 `else if` 链；补 `23w31+ → 1.20.2`、`year >= 24 → 不支持`。

### P5 —— HUD 变换注入点脆弱（issue #3/#4/#6/#13/#14 同源）

- **根因**：6 个 Fabric `InGameHudMixin` 的 post 注入点绑在 `Profiler.push("bossHealth")` 字符串上。历史提交 `5a9f85e` 为修 #3/#4 把注入点从 `renderCrosshair` HEAD/RETURN 改成 `render()` 内 `INVOKE` + `bossHealth`，结构脆弱；字符串标记在不同 MC 版本/被其他模组改动后可能位移或消失，且 `required:true` 注入失败即崩溃。社区 1.21.1 分支（"重铸"）也采用"只变换 crosshair 层"的思路。
- **修复**：6 个 `InGameHudMixin` 的 post 改为
  `@At(value="INVOKE", target=<同 beforeRender 的 renderCrosshair 签名>, shift=At.Shift.AFTER)`，
  与 pre 精确配对，不再依赖 profiler 字符串。变换范围严格限定在 `renderCrosshair` 调用期间。
- **影响**：1.20.1/1.20.2 可见行为基本不变（官方字节码显示两个位置原本就相邻），但旧版本/被改动的 HUD 不再误伤其它元素，且不再因标记缺失崩溃。

### P6 —— TaCZ 兼容脆弱（PR #15 / issue #16 候选）

- **根因**：Forge 侧 4 个 `RenderCrosshairEventMixin` 硬编码第三方内部类、`@Redirect` 目标 `lambda$onRenderOverlay$0` 是编译器生成名；TaCZ 每次更新内部类就可能导致注入失败并因 `required:true` 崩游戏。作者本人在 PR #15 评论中称"用 Mixin 搞兼容太彪悍，每次对方更新这边就得跟着更新"，并计划移除。
- **修复（保留功能、只改失效模式）**：
  - 4 个 Forge mixin 的 16 个 `@Inject` / `@Redirect` 注解全部加 `require = 0`：TaCZ 版本不匹配时该兼容功能自动失效并只产生警告，**不再让游戏崩溃**。
  - 构建期不再需要 TaCZ 的 Fabric 依赖（P0）。
  - `mods.toml` 的 tacz 依赖范围保持 `[1.0.2,)`（比官方 1.10 的 `[1.1.4,)` 更宽松，避免旧 TaCZ 用户被 Forge 依赖检查挡在门外）。
- **未完全解决**：TACZ 的 `onRenderOverlay` 与 vanilla CROSSHAIR 阶段各调一次 `GuiBus.doPre/doPost`，存在重复变换/栈失衡的理论风险；需要装 TaCZ 的完整整合包才能复现，本轮未在游戏内验证，见"未解决事项"。

### P7 —— 配置损坏/类型错误导致模组初始化中断（全部 12 份 `Config`）

- **根因**：`GSON.fromJson(..., Map.class)` 后直接 `CONFIG.putAll(map)`：空文件 → NPE；JSON 语法错 → `JsonSyntaxException`（RuntimeException，只 catch `IOException`）；值写成非 Boolean → `ClassCastException`；`check()` / `getValueText()` 对未知键 NPE。异常从 `MainMod` 构造函数传播到 `FabricLoader` / `ForgeLoader` 后被原实现静默吞掉，实际表现为**模组无功能、日志无异常、配置文件保持损坏**（并非游戏本体直接崩溃）；在配置界面等路径可能直接抛异常。本轮对照实验已复现该静默失效。
- **修复**：解析为 `Object`，逐键校验 `String key + Boolean value + 已定义键`；异常（`IOException | RuntimeException`）时清空并回退默认值、重写配置；`check()` 加空值保护；`getValueText()` 改用 `check(key)`。同时 P12 让入口点异常可见。

### P8 —— CameraOverhaul 兼容硬引用（全部 12 份 `Render`）

- **根因**：直接 import `ModifyCameraTransformCallback` / `Transform`，仅用 `Class.forName` 检测类存在；装了同名但 API 已变的版本（如 issue #11 环境的 1.4.1）→ `NoSuchFieldError` / `NoSuchMethodError` 崩溃。
- **修复**：联动调用整体包 `try { ... } catch (LinkageError | RuntimeException e) { coh = false; }`，失败时禁用联动而非崩溃。

### P9 —— Forge 事件重复注册（6 份 `GuiBus`）

- **根因**：`registered` 标志声明后从未置 `true`，`registerRenderCrosshair` 每次都 `EVENT_BUS.register(GuiBus.class)`。
- **修复**：注册后置 `registered = true`。

### P10 —— `@Overwrite` 窗口标题调试残留

- **根因**：`game/fabric-mixin/src/mixin/.../MinecraftMixin` 用 `@Overwrite` 把 `" <ForgeFabricMixinOne>"` 写进玩家窗口标题；`@Overwrite` 与其它模组冲突风险高，且属调试残留。
- **修复**：删除该类（无功能作用）。

### P11 —— 元数据、文档与文案

- `mod.properties`：`1.9 → 1.10.1`；`MIT → GPL-3.0-only`（仓库 `LICENSE` 与 Modrinth 均为 GPL-3.0，原标注是错误）。
- `readme.md`：补支持范围、构建方法（`gradle buildMod`、`dists/` 产物）、已知限制；回应 PR #15 评论中"缺少编译说明"的反馈。
- `en_us.json`：修正 `"Corsshair"` 拼写。

### P12 —— 入口点异常静默吞掉

- `FabricLoader` / `ForgeLoader` 反射创建 `MainMod` 失败时 catch 全部异常且不输出 → 改为 `e.printStackTrace()`，便于诊断。

### P13 —— `modloader` MixinPlugin 健壮性

- `fs` 为 null、`patchedClasses` 反射只试一个字段名且遍历不继承层级、异常被吞 → 现在：`fs` 空值保护、遍历类层次 + 多候选字段名、失败时给出明确错误；Quilt / 越界版本先短路（P1/P3）。

### 真正根因
`MainMod.preRenderCrossHair` 的变换以 `(getScaledWidth()/2, getScaledHeight()/2)` 为支点做 translate→rotate→scale→translate。对距支点 d 的绘制内容，位移约为 `(s−1)·d + angle·d`：准星在支点处几乎不位移，但准星下方的进度条、以及第三方模组在准星层以其它锚点绘制的 HUD（AppleSkin、Quark UsageTicker、Immersive Aircraft UI 等）会被旋转、缩放并甩离原位 —— 即 30 楼的「进度条乱飞」，与 #3/#6/#13 同源。
矩阵恢复方面：Forge 的 Pre/Post 事件在 Pre 被取消或 Post 未触发时 push 可能残留，影响后续 UI；TaCZ 的 `RenderCrosshairEventMixin` 也调用 `GuiBus.doPre/doPost`，双通道存在重复变换 / 栈失衡风险。

### 修复（不改动画数值、不禁用旋转）
- `game/forge1.20` 与 `game/forge1.20.2` 各新增 `CrosshairRenderMixin`，把变换窗口精确包住 `Gui.renderCrosshair` 内**准星贴图绘制**这一次调用：
  - 1.20 / 1.20.1：`GuiGraphics.blit(ResourceLocation,IIIIII)`，`ordinal=0`，BEFORE 注入 `GuiBus.doPre`、AFTER 注入 `GuiBus.doPost`。
  - 1.20.2：`GuiGraphics.blitSprite(ResourceLocation,IIII)`，`ordinal=0`，同上。
  - 攻击指示器进度条（后续 blit）及所有其它 HUD 落在变换窗口之外；准星本身的摇晃、旋转、缩放、平移全部保留。
- 两个版本的 `GuiBus`：删除 `RenderGuiOverlayEvent.Pre` 的变换触发；新增 `active` 状态、`doPre/doPost` 严格配对、`finishFrame` 在 `Post` 事件兜底恢复矩阵、同帧重复调用保护（防 TaCZ 双通道重复变换）。
- refmap 已核验（产物内 `mixin.xbob.refmap.json`）：1.20 `blit→m_280218_`、1.20.2 `blitSprite→m_292816_`、两者 `renderCrosshair→m_280130_`。

## 8. 第三轮补充修复：原版攻击指示器与准星同步（2026-11-07 晚）

### 问题（用户反馈）
「修复原版的攻击指示器不在跟随准星的问题」：准星随潜行 / 摇晃旋转成 × 时，准星下方的 vanilla 攻击指示器进度条仍保持水平、留在原位，与准星脱节。

### 根因
- 第 7 节的 `CrosshairRenderMixin` 注入在 `Gui.renderCrosshair` 内**第一次 `blit` / `blitSprite`（准星贴图）**的 BEFORE / AFTER。
- 但 `Gui.renderCrosshair(GuiGraphics)` 在**同一个方法体内**、准星贴图之后还会绘制 `attackIndicator=CROSSHAIR` 时的攻击指示器进度条。一手依据 [gui-javap.txt](research/gui-javap.txt) 939–1161 行（1.20.1 `Gui.m_280130_`）：偏移 18/49 两个提前 return、260 首次 `GuiGraphics.blit(m_280218_)` 准星、278 `AttackIndicatorStatus.CROSSHAIR` 判断、412/449/467 攻击指示器 blit、472 `defaultBlendFunc`、475 return。
- 变换窗口只包含第一次 blit → 攻击指示器落在窗口之外，不随准星旋转 / 位移。这与 #6「蓄力条跟随准星」不是同一层问题：vanilla 攻击指示器本来就和准星一起画、应当一起动；第三方 / 其它锚点的 HUD 才应当被排除。

### 修复（保持「其它 HUD 不受影响」的前提下）
- `game/forge1.20` 与 `game/forge1.20.2` 的 `CrosshairRenderMixin` 注入点改为 `@Inject(method = RENDER_CROSSHAIR, at = @At("HEAD"), require = 0)` 调 `GuiBus.doPre(new MatrixStack(guiGraphics.pose()), Minecraft.getInstance().getPartialTick())`，以及 `at = @At("RETURN"), require = 0` 调 `GuiBus.doPost(...)`；`RENDER_CROSSHAIR = "renderCrosshair(Lnet/minecraft/client/gui/GuiGraphics;)V"` 保留，删除 `CROSSHAIR_BLIT` / `CROSSHAIR_SPRITE` 常量。
  - 变换窗口 = 整个 `Gui.renderCrosshair` 方法体：准星 + 它自带的 CROSSHAIR 攻击指示器共用同一套 pose，同步摇晃 / 旋转 / 缩放。
  - `@At("RETURN")` 注入到方法内**所有 RETURN 指令前**（javap 显示该方法有多个提前 return），配合 `GuiBus.doPost` 的 `active` 保护，任意分支只 pop 一次，不会泄漏矩阵；`finishFrame` 仍在 `RenderGuiOverlayEvent.Post` 兜底。
  - **依旧不恢复** `RenderGuiOverlayEvent.Pre/Post` 包裹整个准星层：血条、热键栏、HOTBAR 攻击指示器与第三方 HUD 都画在 `renderCrosshair` 之外，因此不受变换影响，30 楼的「乱飞」不会复发。
- 两个 `GuiBus` 仅改写注释（「renderCrosshair 方法入口」/「每个 return 前」），`active`、`doPre/doPost` 严格配对、`finishFrame` 逻辑不变。
- 不改 `MainMod` 的动画算法与任何配置键、不禁用旋转；`class_1309` / Quilt / 越界版本等前几轮修复不受影响。
- 源码改动范围：4 个文件（`git diff` 4 files +34/-21，仅两个 `CrosshairRenderMixin` 与两个 `GuiBus`）；其余为文档 / 发布文案同步更新（同一次提交，共 11 files +128/-36）。修复前 JAR 备份 `research/before-attack-indicator-fix-1.10.1.jar`（302463 B）。
